# Synthetic example: Workday Reflection excerpt

This example is synthetic. It is not a real Workday Reflection and should not be copied into a private portfolio or Workday.

## Purpose

Show how `/draft-reflection` can turn sourced career evidence into clean Workday-ready prose while keeping private source comments out of the pasted answer.

## Scenario

The user has captured an impact note about improving a planning workflow, a peer feedback entry approved for reflection use, and a current goal about making cross-functional work easier to start.

## Input

```text
Draft my reflection using the kickoff checklist impact note, the approved feedback about decision clarity, and my goal around improving cross-functional planning.
```

## Output

```md
## Q1. What results did you deliver, and how did you do it?

I improved how cross-functional projects start by redesigning the kickoff checklist that contributors use before the first planning meeting. The prior process left too much room for different assumptions about owners, dependencies, and decisions, which meant planning meetings often had to spend time aligning on basics before the team could discuss trade-offs. I simplified the checklist around the contributor experience, separated required pre-work from optional context, and added clearer prompts for owners, blockers, and decision points.

The main result was a clearer preparation path for new contributors and project leads. A peer partner shared that the decision summary made it easier to see what had been agreed on and what still needed follow-up. That feedback showed the work was not just documentation cleanup, it helped the group move from discussion to action with less ambiguity. I still need stronger usage data, so my next step is to capture whether the checklist is being reused across additional projects and whether it changes meeting quality over time.

<!-- Q1: 177 words, recommended 450-650 -->

```

## Why it works

- It starts with the result, not the task.
- It connects the work to a real behavior change signal.
- It names the evidence gap instead of overstating impact.
- It keeps source comments private and outside the Workday-ready prose.

## Privacy note

The example uses synthetic source paths and generic work. It contains no real names, issue numbers, PR numbers, Slack URLs, customer names, or recognizable internal incidents.

## Reuse path

Use this as a pattern for evidence-backed reflection writing. Replace the scenario, source files, feedback, and outcomes with your own verified evidence.
