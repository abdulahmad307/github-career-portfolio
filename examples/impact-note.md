# Synthetic example: impact note

This example is synthetic. It is not real employee evidence and should not be copied into a private portfolio.

## Purpose

Show how `/new-impact-note` can turn a thin accomplishment into a useful note while preserving unknowns instead of inventing metrics.

The example uses the same core fields as `impact-notes/TEMPLATE.md`: Work moment, Why it mattered, What changed, Evidence, How I worked, and Who benefited. Examples can add richer narrative or teaching notes, but real notes should preserve those fields so downstream workflows can read them consistently.

## Scenario

An IC helped reduce onboarding confusion for a cross-functional internal workflow. The work shipped, but final adoption metrics are not available yet.

## Input

```text
I redesigned our project kickoff checklist so new contributors know what to do before the first planning meeting.
```

## Output

```md
# Project kickoff checklist refresh

**Date:** 2026-05-05

## Work moment

I redesigned the project kickoff checklist so new contributors have a clearer path before the first planning meeting.

## Why it mattered

New contributors were arriving at planning meetings with different assumptions about goals, owners, dependencies, and decision points. The updated checklist created one place to prepare before the meeting.

## What changed

The checklist now separates required pre-work from optional context, names the expected owner for each section, and gives contributors a clearer way to flag blockers before the meeting.

Results are not captured yet.

## Evidence

- Link or screenshot to add later.
- Adoption or meeting-quality signal to add later.

## How I worked

I simplified the workflow around the contributor experience instead of adding more process. I kept the checklist lightweight so it would support preparation without making kickoff feel heavier.

## Who benefited

New contributors, project leads, and cross-functional partners preparing for kickoff.

## Questions to answer later

1. Did kickoff meetings become shorter or clearer after the checklist changed?
2. Which teams or roles used the updated checklist?
3. Is there feedback from a contributor or project lead that shows the change helped?
```

## Why it works

- It captures what shipped and why it mattered.
- It avoids invented numbers.
- It names missing evidence as follow-up instead of pretending the evidence exists.
- It records judgment and trade-offs in "How I worked" without overstating the impact.

## Privacy note

The scenario uses generic internal-workflow language. It includes no real names, links, issue numbers, PR numbers, customer names, or recognizable incidents.

## Reuse path

Use this as a pattern for structure and level of detail. Replace the scenario with your own real accomplishment, evidence, and unknowns.
